# Domain workflows

Use these terms to find current commands with `symphony_discover`; use `symphony_describe` for the executable contract. The map records ownership and practical interpretation. It is not a static feature inventory or an assertion that each installation has these engines.

## Knowledge, modules, and lifecycle

Search `knowledge`, `modules`, `engines`, `contracts`, `invariant`, `feature`, `lifecycle`, `session`, `reconcile`, or `binding` according to the task. Check exact receipt and binding state before selecting a module. Report source validation, installed-file verification, and live readiness separately. qxctl is the administration interface; the semantic owner remains responsible for its operation.

## SSIAG and STAV

Search `ssiag` for identity, provider trust, policy, enrollment, and supervision; search `stav` for audit status, bounded query, verification, enrollment, and supervision. Keep TOPS and scope explicit. Describe each command's mutability before dispatching it: some verification and recovery workflows can update retained state.

Use the native operation's evidence and recovery path. The bridge does not make an authority decision or receive raw audit append authority. A provider trust descriptor and a usable provider credential are different facts.

## SCV: provider knowledge

Search `scv` and the selected provider, source, corpus, graph, composition, publication, or transfer terminology. Preserve original source revision, capture, asserted fact, derived conclusion, and coverage state. A source may be discovered but unacquired, acquired but uninterpreted, or partly qualified.

Provider knowledge does not establish that SOV can provision that resource. Compare providers using relevant evidence and user requirements; do not silently select a preferred provider or change exact API versions. Source refresh and protected knowledge selection can have different owners and mutability.

## SHV: hardware knowledge

Search `shv`, then the catalogue, source, dossier, profile, graph, inventory, or publication operation relevant to the question. Preserve exact hardware subject identity, source association, date precision, unknown fields, and requested coverage. Model introduction, manufacture date, selected configuration, and measured behavior are distinct.

A graph mapping or hardware capability claim is not whole-system compatibility. A package image alone is not a complete conditioned Habitat. Do not infer eligibility from vendor branding or silently replace user-selected hardware.

## SNV: Node facts and relationships

Search `snv`, `sniv`, `snrv`, `sciv`, or `scnv` where advertised. Node identity, resource observations, cluster relationships, and naming records are distinct. Preserve supplied versus observed evidence, scope, time, provenance, and uncertainty.

SNV records assigned identities and names; it does not choose them for the user. A Node record does not prove that provisioning or remote access succeeded. An optional local observer's selected measurements do not imply a general monitoring agent.

## SQV: quantitative data capabilities

Search `sqv` and the relevant capture, metadata, flow, conversion, retention, delivery, replay, or source-adapter term. Discover the exact installed owner. Preserve original bytes, schemas, units, timestamps, sequence/checkpoint boundaries, and source lineage where the contract requires them.

Read-only retained-state inspection does not imply live collection, authenticated provider execution, broker access, or FIX support. Keep a request/configuration validation result distinct from execution. Do not turn a configurable research-data tool into a prescription for users' strategy logic or feed topology.

## SBV: research and backtesting

Search `sbv` for the caller's selected census, replay, dataset, model, experiment, fitting, comparison, account, result, or job work. Discover its currently installed source and engine contracts before executing. Preserve exact input identity, model choice, resources, result lineage, evidence of new versus reused work, and the distinction between observed data and synthetic/model-produced values.

Retrieve retained results through their actual result interfaces, including pagination or selection when offered. Do not infer missing terminal results from a summary. A theoretical probability, synthetic fill, or simulated cash path is not empirical market truth or proof of live trading behavior. Users may choose models, policies, optional adapters, and research compositions.

## SOV: operations and selected remote work

Search `sov` for the specific task and inspect its command contract. The inspected source baseline includes bounded remote SBV job/result operations and an optional SSH carrier. It does not provide arbitrary remote administration through this plugin.

Preserve exact target, operation ID, transport profile, installed runtime, authorization, and observed result state. A local planning result or supplied observation is not a completed deployment. Provider provisioning, Habitat conditioning, Nest delivery, bus setup, and Prima Parte remain subject to their own implemented contracts and qualification; do not manufacture commands for them.

## Other modules and future adapters

Search the installation rather than assuming this list is exhaustive. SIV, SAIV, SMCV, SOOV, and other names in design material must not be represented as implemented just because they are named. Optional translators and adapters do not gain semantic authority by changing a wire format. Missing functionality is an explicit extension opportunity, not a ban on the user's chosen system.
