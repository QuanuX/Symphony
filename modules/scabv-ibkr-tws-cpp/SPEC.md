# IBKR TWS Stable read adapter boundary: exact 0.1.0-dev contract

## Supported extent

Duncan selected the Stable line, observed as exact SDK 10.45 on 2026-09-28, and confirmed no authorized local SDK. The adapter therefore includes a typed external-SDK template and tested callback collector, without downloading, accepting terms for or bundling IBKR code. Sdk1045Driver instantiates against the authorized EClient, Contract and TagValueListSPtr types. It calls only reqPositionsMulti/cancelPositionsMulti and reqHistoricalData/cancelHistoricalData. Historical requests use TRADES, useRTH=1, formatDate=2 and keepUpToDate=false. The embedding SDK owner must provide an authenticated account session, the concrete vendor transport and exact callback routing. The optional host Session supplies read request IDs, local pacing and lifecycle admission within one exclusive client-ID owner. Collector binds account/model, request ID and session generation. Wrong generation/ID is refused; malformed or wrong-account matching callbacks close the request as failed. Finite records 1–100,000, callback payload 1 KiB–64 MiB plus a separately bounded 4 KiB snapshot header, and deadline 1–300,000 ms. Caller drives poll and its stop token; no hidden polling thread exists. End markers send cancellation and close local callback admission. Cancellation dispatch is not a provider acknowledgment. Disconnect, error, cancellation, resource or allocation failure never becomes complete data. Mutex serialization covers concurrent callbacks; reset/move/destruction must not race any method. Driver must outlive Collector and not reenter it synchronously. After fork methods refuse; destruction does not call the inherited Driver. Callback projections retain exact IEEE754 price bits, native decimal strings, selected contract fields and provider end evidence; these are explicitly selected callback fields, not original TWS wire frames. Complete means the initial provider response reached its end marker, not an atomic account state.

## Host session ownership

`Session` is an optional serialized host coordinator over `RuntimeDriver`, not a vendor SDK implementation. The runtime connects only the explicitly selected loopback host/port/client ID; login remains external. Each connection attempt receives a new generation derived from a caller-unique session tag. `nextValidId` admits readiness only and does not seed read IDs; a bounded, duplicate-free `managedAccounts` list must also contain the selected account. The host converts the provider list without inventing entries. A failed or timed-out handshake closes the transport. Session callbacks from earlier generations and unrelated request IDs cannot affect the active collector.

Only one finite read may be active. Request identity fields must be unset; the coordinator inserts its bound account/model/private scope and monotonically allocates positive signed-32-bit read IDs. An attempted ID is never reused, including failed dispatch or reconnect; exhaustion refuses. Host ownership of the client ID and no competing request allocator are prerequisites. Starts are separated by at least 100 ms; historical starts by at least 16 seconds across reconnects. This conservative local budget covers this Session only; the host must coordinate other sessions and provider-specific limits. Refusals return `limit` without queueing or sleeping. Invalid attempts may consume a local ID/budget, but never dispatch an invalid request.

The runtime pump must drain bounded queued EReader input on the owner thread and return; the host owns socket/reader shutdown and joining. Only pump may synchronously deliver callbacks. Other runtime methods must not reenter Session or Collector. Methods, destruction and reset are serialized by the host. Forked children refuse without calling the inherited runtime. Deadline/stop, failed dispatch and disconnect leave terminal gap snapshots. A terminal request must be explicitly released before another start or reconnect. There is no automatic reconnect, replay or cancellation acknowledgment. A preflight open failure preserves output; once connection dispatch starts a failed Session is retained. `poll` returns `stale` when an end callback completed the collector; `snapshot` then reports its terminal state.

## Native/package boundary

C++26, initially verified on macOS amd64 / AppleClang 21 with compatible native consumers. Fallible preparation/admission preserves output on failure unless the API explicitly reports an attempted operation. Immutable handles may be retained; mutation, reset, destruction and move must not race use of the same handle. Source data is untrusted. Errors contain status only, never source contents or credentials. Dependencies: native-source-support-cpp 0.1.0-dev, sqav-capture-cpp 0.2.0-dev. No runtime discovery or implicit upgrade. The module exports no standalone process or qxctl command.

## Verification and limits

`tests/test.cpp` exercises supported positive and negative boundaries; `tests/sdk-consumer/main.cpp` exercises the installed public API outside the checkout. The SQV non-live source composition tests preserve selected capture evidence through exact local retention/replay. The tests and package receipts do not establish provider access, production conformance or a licence grant.

No installed or licensed vendor SDK, verified SDK 10.45 conformance, concrete vendor socket/EReader/EWrapper/Decimal bridge, login automation, live collection, order entry, provider cancellation receipt or operational SSIAG authorization. Host session fixtures do not establish SDK or operational acceptance.
