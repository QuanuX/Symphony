# SOV Cloudflare adapter spec

This independently installed C++26 component implements the subordinate SOV owner defined in `knowledge/sov/cloudflare/SPEC.md`.

The reviewed November 7 C0/I1 target is implemented only for the operation set in `owner.json`. The remaining M1-01 through M1-07 requirements stay mandatory at I6. See `c0/README.md` and `VERIFICATION.md` for observed scope.

## Process contract

One request/one result uses `symphony.sov.cloudflare-request.v1` and `symphony.sov.cloudflare-result.v1`, bounded to less than 8 MiB. `--describe` emits only the compiled owner declaration. Installed qxctl verifies the entire receipt-v2 package, stages an exact executable copy and binds its digest, receipt digest, version and owner digest. Native checks its own executable and declaration before work. qxctl validates result correlation and complete safe text/JSON output. It never forwards raw child diagnostics. Errors use exit 5 when a bound result exists, 2 for unusable control framing. No automatic retry.

`owner.json` defines the closed input schemas and safe templates; null fields are explicit. Duplicate, missing, unknown or aliased keys, trailing JSON, non-UTF8 and floating values reject. Sizes are bounded integers; generations/expiry/UIDs are canonical decimal strings. Canonical bytes are UTF8, sorted object keys, no whitespace, literal non-control Unicode, JSON escapes for quotes/backslash/control characters, decimal integers, explicit nulls and preserved array order. The digest is `sha256:` plus lowercase SHA256 of domain + NUL + canonical body. It is not RFC 8785. Plan/bundle/state/owner domains are their exact protocol strings. Independent fixed golden vectors and Go fixtures cover this encoding.

Result axes preserve local dispatch and effects. Reads complete with `not_applicable`; a verified local lifecycle commit has `applied_verified`. A lost mutation result is `unknown`/`unresolved`; status/reconcile inspect the same plan and never replay it. Local lifecycle authority reports the kernel UID. Credentialed operations return SSIAG policy and committed STAV audit references; those are independent of provider effect verification.

## Local toolchain lifecycle

`installation.plan` creates the explicitly named private store if absent, its lock and durable content-addressed plan. Other commands do not bootstrap it. Parent directories must be canonical nonsymlink directories without group/world write access (root-owned sticky temp ancestors are allowed); the store is owned by the actual non-root UID and mode 0700. No sudo identity inference. One nonblocking exclusive store lock serializes plans and mutations.

Installation consumes an already prepared offline bundle, never invokes npm or scripts, never downloads and never selects partial content. `cloudflare-prepare_bundle` assembles a previously verified Node distribution and script-disabled npm tree, excluding unused npm .bin links. All remaining files, runtime, lock, licenses and transitive modules are inventoried. Bundle admission checks exact files, sizes, hashes, platform, regular file type, modes and absence of symlinks/hardlinks. It detects extras as well as missing files. An integrity-valid imported bundle is not automatically qualified for execution. Offline execution requires an explicit manifest digest in the owner's qualified toolchain list.

Install publishes a complete verified copy and leaves it unselected. Select binds a retained exact installation. Update imports a new exact bundle and selects it while retaining earlier content. Rollback selects a retained qualified-by-caller installation without reinstalling. Remove refuses the selected installation, retires only exact local package files and retains a tombstone. Inspection reports the complete package inventory. No installation action deletes a Cloudflare resource.

Plans bind input, store, UID, exact adapter/descriptor, prior state, resulting state and toolchain identity; validity is one hour. Initial state must be requested explicitly with null expected_state. Later plans require the exact current state digest. Generation increases even for identical selections. Apply rechecks full input integrity and expected state before durable prepared/admitted/dispatch_started intent, then package and state publication, observation and settlement. A used plan never executes again. Unsettled attempts close further apply admission. Reconcile observes committed state or provably pre-dispatch intent. With the prior state still authoritative, explicit reconcile reclaims an unselected incomplete/imported copy or restores an exactly retired package, then settles no net effect. A committed state is verified and settled without replay. Foreign/conflicting state remains unresolved; no binary or installation is reexecuted. Files and containing directories are fsynced, subject to the actual filesystem's durability guarantees.

## Offline cf execution and context

Offline discovery executes bounded `cli search` and the exact schema argv candidates in the declaration. Search is up to five ranked matches, explicitly not a complete vendor inventory; generated schemas may be incomplete. Node 26.12.0 runs with `--permission`, read access only to the exact bundle and empty private working directory, no network/write/child/addon grants. Environment is constructed from fixed values. `CF_DELEGATION=1` disables the selected beta's local handoff; telemetry and update checks are disabled. No token, NODE_OPTIONS, proxy environment, ambient home or project configuration is inherited. Full dependency integrity is checked before and after execution. A 20-second deadline and bounded output apply to these descriptors only; cancellation via qxctl terminates its process group including Node.

Context administration and credentialed execution are specified in the I4 sections below. Project build/deploy remains a separately gated I7 surface.

## Trust and qualification limits

This is a user-owned local file lifecycle, not a defense against a hostile process with the same UID or a hostile root. Protected immutable package trust for transport profiles is a separate I2 prerequisite. The selected macOS runtime depends on system libraries; exact system build and dependency observations are recorded in C0. Linux/ARM source paths are intended but not locally qualified. Existing SSH v1 is neither modified nor governed by this new non-root rule.

## I4 credentialed resource execution

`resource.plan` preserves credentialless previews with execution=null. An execution selection names the independently installed native SSIAG private-store provider, exact receipt/version, private vault/configuration digest, reference generation, optional sensitive result reference and maximum pages. The plan binds the provider configuration, consuming adapter and qualified toolchain. Missing admission never falls back to ambient credentials. Tunnel create/get/token retrieval require a result reference before dispatch. Token rotation is absent from cf 1.0.0-beta.28 and remains unsupported; M1-02/I6 stays open.

SSIAG's `/v1/cloudflare/use` admits the exact operation/account/zone/resource under a mapped non-root principal and committed STAV intent. Native peer/executable checks bind the private credential channel. Go SSIAG and qxctl see metadata only. The policy pin lasts through bounded use and cleanup. Native credentials are purpose-, target-, generation- and expiry-bound. See `modules/ssiag-provider-private-store/SPEC.md` for store opt-in, generation revocation, sensitive import, trust limits and deployment requirements.

The 23 closed Tunnel/DNS/Access profiles execute the pinned Node/cf entrypoint with constructed environment and private scratch. The SDK's selected authentication path sets maxRetries=0. The receipt-owned fetch guard permits exactly one matching API URL/method/body per child, forbids redirects and subsequent fetches, bounds response bytes, and drops all error bodies. Node read permissions exclude ambient home/project/configuration; no subprocess/addon/write grants exist. Raw stdout/stderr are discarded. DELETE adds the explicitly qualified --force flag. A child has a 20-second deadline within the authority lease; no automatic replay occurs. Full bundle integrity is checked before and after dispatch. This guard constrains the selected trusted CLI's fetch path; it is not a universal network firewall for arbitrary executables.

`resource.list` and `resource.inspect` execute persisted read plans. List observations retain explicit page range, next page, timestamp, scope and completeness. Bounded pages never imply complete inventory. Safe projections admit only profile fields; unknown/sensitive raw fields stay private. A separate sensitive-result frame imports Tunnel tokens and raw sensitive Tunnel results at the native owner, returning only opaque references. No secret-bearing raw body or its digest becomes an evidence artifact.

`resource.apply` requires a retained complete prior observation, performs a fresh scope/state comparison, journals intent before mutation, executes once, and reads back independently before applied_verified. This is preflight_only, not an atomic Cloudflare conditional write. Create needs complete collection observation; update/delete need exact object observation. Deletion verifies absence in complete inventory. Status reads the journal. Reconcile obtains fresh read authority and observes without repeating the mutation. A lost sensitive-import acknowledgment stays unresolved and directs inspection of native import metadata; recovery does not repeat the token endpoint or silently drop its required result. Unknown creates without a returned ID stay unresolved; reconciliation never guesses ownership by name. An unresolved attempt blocks new resource and local lifecycle mutations. Audit loss or ambiguous effects never become success.

## I4 contexts and connector lifecycle

Context inspect/plan validates the explicit record and installed toolchain; plan stores current generation and proposed selection. Apply compares the exact prior state, publishes the nonsecret selection and retains a private journal. Status/reconcile inspect and settle the same plan without replay. Explicit resource inputs remain bound to their own context; stored selection does not provide implicit account or credential defaults. A host_ref is a label, not host authentication.

`qxctl sov cloudflare connector {installation,instance} {list,inspect,plan,apply,status,reconcile}` owns a separate user store. Package intents install/select/update/rollback/remove the exact digest-qualified cloudflared executable; no downloader, script, privileged service installer or automatic update runs. Instance intents configure/start/stop/update/retire one selected managed Tunnel per store. Configuration selects account, Tunnel UUID, exact binary and purpose-bound native credential reference. Update/retirement require a stopped instance; retained package versions support explicit rollback. Selected packages cannot be removed.

Start journals first, obtains SSIAG authority and a Tunnel token, and launches a persistent native supervisor with a retained exact executable copy. It supplies TUNNEL_TOKEN only to cloudflared, uses an empty private YAML configuration and explicit Tunnel UUID, disables automatic update, discards logs, and binds metrics to loopback on an ephemeral port. The selected upstream process therefore opens its explicit loopback metrics listener; it does not open a Symphony public listener. Configuration is remotely managed at Cloudflare. The supervisor runs as the actual user, reaps its own child/process group and exposes only authenticated private status/stop IPC. Stop verifies the actual supervisor executable and instance binding, never sends a signal to an unverified saved PID. Root execution refuses; no sudo flag is introduced here.

A successful start proves local process liveness and admitted credential use, not provider connectivity; provider_readiness remains not_proven. A persistent connector is an explicit lifecycle effect and survives qxctl's return. Provider reconnect behavior belongs to cloudflared, distinct from mutation retries. Local credential revocation does not terminate existing sessions; explicit stop does. Unexpected supervisor loss can leave uncertain process state; status/reconcile refuse a successful claim when authenticated observation is unavailable. Private runtime paths must fit the platform Unix-socket length. Unresolved journals prevent relaunch. Lost-start reconciliation can observe the existing supervisor but never spawn another.

## I4 qualification boundary

The code implements the bounded administration surface and both native credential channels. Source/fixture qualification is separate from actual Cloudflare operations: no live account/zone, real token, provider mutation, Access session or SSH connection is used by local tests. cf 1.0.0-beta.28 / Node 26.12.0 and cloudflared 2026.10.7 retain exact selected identities. Concrete runtime digest qualification currently selects the C0 macOS amd64 artifacts; additional binaries/platforms require separate admission. Connector lifecycle fixtures use an inert native child and cannot establish Cloudflare connectivity. Token rotation, live I6 acceptance and I5 Access SSH sessions remain explicitly open. Direct SSH v1 and protected v2 profile publication/admission are unchanged.

I5 adds the receipt-owned `symphony-cloudflare-access` native entry point under the
same SOV component. The normative subordinate contract is
`knowledge/sov/CLOUDFLARE-ACCESS-SESSIONS.md`; the closed schema projection is
`knowledge/sov/cloudflare/access-sessions.json`. Local same-user session semantics
and the explicit protected runtime are implemented. Actual pinned-binary/live
Access SSH qualification is separately required; installation does not assert it.
