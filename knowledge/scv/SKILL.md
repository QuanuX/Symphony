# Symphony Cloud Vector Skill

## Purpose

Guide agents and implementers in SCV research without introducing provider preference or mistaking observations for authority.

## Reading Order

1. `knowledge/ARCHITECTURE.md`
2. `knowledge/SLANG.md`
3. `knowledge/NAMESPACES.md`
4. `knowledge/scv/INTENT.md`
5. `knowledge/scv/MANIFEST.md`
6. `knowledge/scv/SPEC.md`
7. applicable SOV, SNV, SHV, SACV, SSIAG, STAV, and SODV contracts

## Procedure

1. Record the user's declared provider, region, account, and topology constraints without widening them.
2. Separate provider fact, private account observation, local measurement, user declaration, and derived comparison.
3. Preserve source, version, observation time, uncertainty, conflict, and staleness.
4. Compare exact capabilities without ranking providers.
5. Keep SCV semantic output separate from SOV operational permission.
6. Keep all private installation facts outside official source and public documentation.

## Stop Conditions

Use the admitted source-knowledge operations and owner-selected source definitions within `knowledge/scv/SOURCE-KNOWLEDGE.md`. Preserve unknown formats and unverified interpretation. New graph technology, semantic schema, operational account adapter, authority boundary, scoring policy or network API beyond that contract requires a separate reviewed decision; ordinary authorized use does not reopen an already ratified boundary.
