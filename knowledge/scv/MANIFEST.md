## Admitted Implementation Character

The 2026-09-10 source-knowledge increment admits the independently installable C++26 SCV, SCHV, SCEV, SCHV-AWS, SCHV-AZURE, SCHV-DO, SCHV-GCP and SCEV-CF engines. `knowledge/scv/SOURCE-KNOWLEDGE.md` and its v1 schemas own the bounded source, capture, interpretation and graph semantics. Each package shares explicit implementation mechanics while retaining its own domain, receipt and installation. The additive `0.2.0-dev` increment assigns bounded capture indexes, immutable corpus snapshots, explicit evidence selection and corpus differences to `knowledge/scv/CORPUS.md`. qxctl retains exact corpus evidence without adding a selected corpus head. Existing `0.1.0-dev` installations and data shapes remain compatible at their exact scope. The additive `0.3.0-dev` profile in `knowledge/scv/INTERPRETATION.md` adds exact reusable mappings, scoped connection checks and retained-result reassessment. Existing `0.2.0-dev` corpus and `0.1.0-dev` source/knowledge operations remain invocable at their exact versions. Native provider knowledge precedes optional common capability projections. Complete provider corpora, arbitrary graph connectors, account operations and a network API remain unimplemented or separately scoped.

## Reproducibility

An independently installed SCV implementation must be able to construct its graph from the same defined evidence process and data points used to build the original. Shipping a private prebuilt database is not a substitute for that contract.

## Non-Authorization Statement

This manifest grants no provider login, account query, balance persistence, credential release, purchase, provisioning action, network service or graph database selection. The admitted qxctl source-knowledge mappings administer only their declared evidence and protected local-state scope.
