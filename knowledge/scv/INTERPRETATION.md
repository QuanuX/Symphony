# SCV Provider Interpretation and Connection Contract v1

## Scope and Version

Engine `0.3.0-dev` adds three pure operations to the existing seventeen: `provider_interpret`, `connection_evaluate` and `connection_reassess`. All eight independently installed SCV, family and provider packages expose the same bounded mechanics within their declared domain. This companion owns the interpretation-profile, provider-interpretation and connection-operation schemas under `knowledge/scv/schemas/v1/`. The previous nine schema artifacts and their data shapes remain unchanged.

This increment applies explicit reusable semantic mappings to retained provider text, evaluates caller-defined connection checks and compares exact earlier/later results. It does not comprehend arbitrary documentation, prove complete provider expertise or implement a Composer. Native text extraction, semantic mapping, evidence support and runtime verification remain distinct. A profile can be authored by a human or permitted agent; its authorship is provenance, not publisher endorsement, authority or a mandatory human review step.

| Operation | Request definition | Result protocol | qxctl scv leaf | Interaction |
| --- | --- | --- | --- | --- |
| `provider_interpret` | `providerInterpretInput` | `symphony.scv.provider-interpretation.v1` | `provider interpret` | invoke, evidence only |
| `connection_evaluate` | `connectionEvaluateInput` | `symphony.scv.connection-evaluation.v1` | `connection evaluate` | validate, evidence only |
| `connection_reassess` | `connectionReassessInput` | `symphony.scv.connection-reassessment.v1` | `connection reassess` | validate, evidence only |

Descriptor input protocols select named request definitions and do not add a protocol field inside the payload. The common process v1, descriptor v2, immutable receipt v2, explicit domain and byte/value/deadline limits remain in force. Package `0.1.0-dev` retains thirteen operations, `0.2.0-dev` retains seventeen and `0.3.0-dev` has exactly twenty. Existing leaf defaults remain `0.1.0-dev`; corpus leaves default to `0.2.0-dev` and explicitly permit `0.3.0-dev`; the three new leaves default to `0.3.0-dev`. Exact receipt selection cannot substitute another installed version.

## Profiles, Bindings and Replay

`provider_interpret` receives `{captures,profiles,bindings,selection_policy}`. Captures and policy use the existing v1 contracts. Each binding names an exact profile digest and capture digest. Every supplied profile and capture is explicitly bound, and each profile has exactly one binding. Profile IDs are unique within the selected interpretation and across wrappers selected for one connection evaluation, so each stable profile/capture association is unambiguous. This is a bounded `0.3.0-dev` tool constraint, not a global namespace allocation or a restriction on independently authored programs. At most sixteen bindings and 128 rules across the request are admitted. No source-name lookup or latest profile selection is implied.

A sealed profile retains protocol, profile ID, exact opaque profile version, provider/source/locator identity, admitted media types, author, rationale, rules and digest. Its identity selectors must match the bound capture. Neither the author field nor a content seal establishes publisher authority. Changing the selected mapping creates different exact profile evidence even if the upstream body is unchanged. Reusing a mapping requires no new model call.

Each rule retains its own ID, generated claim ID, subject, predicate, complete scope, statement kind, dependencies, literal context and extractor. Existing claim types, scope and dependency semantics are reused. Zero to eight context strings are permitted; each required string must occur exactly once. A literal extractor requires one unique exact quote and an explicit typed value including unit. A delimited extractor requires nonempty literal prefix/suffix delimiters around one unique bounded integer, decimal or string token. Integers and decimals retain the existing canonical exact ranges and representations. There is no floating-point promotion, unit conversion, regular-expression language or executable selector. String tokens retain exact native spelling and support equality only.

All matched context and the extracted quote become retained claim evidence. Missing or ambiguous context/value, invalid tokens and unsupported media produce explicit unresolved extraction findings with no claim. An invalid profile is rejected as a request error rather than silently dropping malformed rules. Failed captures cannot produce claims. Partial captures retain the existing explicit policy and qualification. An extraction match proves the occurrence and declared mapping; it does not prove the interpretation's semantic correctness or live service behavior. Material outside selected context fragments remains unassessed.

The sealed interpretation result retains exact sorted profiles and bindings, ordinary v1 knowledge, each rule's matched/unresolved finding and limitations. Each extraction identifies its exact profile, capture, rule and claim. The embedded knowledge retains exact captures, policy and generated claims under a deterministic interpreter identity. Consumers claiming this profile provenance must retain and replay the wrapper; a bare graph cannot silently replace it. Replay reconstructs the entire sealed result, rejecting modified fields even if a caller recomputes the outer digest. Enumeration order of captures/profiles does not change the normalized output.

## Explicit Connection Checks

`connection_evaluate` receives `{interpretations,additional_knowledge,query_time,connections}`. Every interpretation wrapper is replayed before its knowledge is used. Explicit additional ordinary knowledge accommodates user assertions, supplied observations and independently authored modules. The combined selection admits at most sixteen knowledge artifacts and requires at least one, under the existing composed capture/claim bounds and common selected policy. The engine builds an ordinary v1 graph from that selected collection and applies its existing support, conflict, policy and freshness evaluation at the supplied whole-second UTC time. It does not infer permission or silently broaden coverage.

A connection names its ID, from/to subject labels and checks. Endpoint labels describe the caller's composition; they do not allocate Nodes, prove a route or forbid other user programs. At most 32 connections and 128 checks across the request are admitted. Each check records its ID, caller-selected required/optional importance, left claim reference, operator and right claim reference or literal typed value. Claim references name the claim ID, exact subject and complete scope. Matching a name while discarding region, plan, mode, cohort, version or other qualifiers is not allowed.

Comparisons use `eq`, `gte` or `lte`. Types and units must match exactly. Ordering is numeric only and preserves exact integer/decimal semantics; there is no special cross-type promotion or unit conversion. Missing, expired, disputed or unsupported claims, unresolved extraction and scope/type/unit mismatch yield unresolved checks. Conditional graph support or a statement kind other than documented fact or requirement yields a conditional check with its comparison retained. A recommendation, user assumption or observation does not silently become a universal documented capability constraint.

Each check returns its specification, status, reasons, referenced claim IDs and a boolean or null comparison. Status is satisfied, contradicted, conditional or unresolved. Required checks aggregate in that order of precedence: contradicted, unresolved, conditional, satisfied. No required checks yields unresolved. Optional checks stay visible but do not determine aggregate status. The caller decides which checks are required and which experiments or compositions to pursue; the engine neither relaxes a requirement nor chooses a topology.

Satisfied means the selected documented checks match at the specified evidence time. It does not prove account availability, authorization, installed adapters, network routing, payload agreement, capacity or a deployed workload. Those requirements can be represented by explicit checks and unresolved evidence where applicable. Contradiction is scoped to the selected statements and caller requirement, never a provider-wide rejection. Default and maximum values require separately authored predicates and context; the engine does not infer their interchangeability.

The result retains the exact evaluation input, graph digest, full graph evaluation, connection/check findings and limitations. A graph digest binds a result to its selected graph; the retained input and wrapper replay provide its reconstructable provenance. Matching source text, multiple citations and repeated body bytes do not manufacture semantic verification or independent support. Existing support-cycle, alternative-support and conflict qualifications remain visible.

## Change and Reassessment

`connection_reassess` receives exact retained `{before,after}` connection-evaluation results. Both are replayed from their retained inputs before comparison; a digest-valid but forged result fails. The output binds both result digests and reports boolean axes named `captures`, `profiles`, `additional_knowledge`, `selection_policy`, `requirements` and `query_time`. The profiles axis compares exact selected profile digests; the captures axis includes retained capture digests and resolved `{profile_id,capture_digest}` associations. An unchanged profile applied to a refreshed capture changes the captures axis without claiming a profile revision. A profile-only revision with the same stable association changes profiles without claiming a capture change. These axes identify changed inputs, not a counterfactual proof of causation.

Each union-keyed `{connection_id,check_id}` record retains earlier/later status, changed and affected. Missing sides are null. Changed compares complete check results. Affected also accounts for changed referenced graph findings, including their dependency, evidence and freshness qualifications. A changed profile can matter without changed source bytes; elapsed time can expire support without a new graph or source revision. Additional or removed coverage can matter independently of existing claim values. Unchanged unrelated findings remain separately identifiable.

Earlier artifacts remain immutable. Reassessment does not update a selected graph, fetch missing sources, retire services, substitute a provider or execute remediation. Simultaneous policy, profile, evidence and requirement changes cannot be attributed solely to the provider. The result assesses only the finite retained inputs and dependency relationships supported by this implementation.

## Administration and Acceptance

qxctl exposes the three pure owner operations through bounded input files and exact receipt-backed invocation. Results are evidence artifacts. No protected source/graph head mutation, corpus head, credential use, SSIAG authority expansion, STAV write receipt, daemon or provider action is introduced. Existing deliberate source and graph selection retain their own authorization, audit and recovery contracts. A user may retain or share private interpretation results under their own applicable policy.

The source contract and schemas describe exact structure; runtime adds byte, digest, strict time, uniqueness, total-count and replay checks. Existing capture/knowledge/graph limits apply to composed results as well as each input. A request within a rule count may still exceed aggregate JSON or byte limits and must fail explicitly. Interpreted coverage is selected rules over selected captures, never an invented percentage of provider knowledge.

Acceptance requires owner producer tests, independently rejecting consumer tests and actual receipt-backed process tests for all eight domain packages. Cases cover deterministic order-independent replay, changed numeric evidence with unchanged profiles, missing/ambiguous context, exact types/units and qualifiers, recommendation/default distinctions, missing runtime requirements, time-only expiry, independent support and unrelated findings, changed-profile/requirement axes and resealed forged results. Test names establish traceability; actual test execution and any selected live/synthetic demonstrations are recorded separately in the completed change's evidence and append-only SCLV closure.
