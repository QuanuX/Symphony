# Symphony Backtesting Vector specification

SBV is an evolvable VGAA vector. Its initial executable owner is `modules/sbv-engine/SPEC.md`. The October 5 white paper and plan are design provenance held in the project context, not evidence that every proposed subvector or study is implemented. Candidate subdivisions remain proposals until their boundaries are justified and independently registered.

The current release implements closed-census historical research, exact rational scenario composition and complete terminal/portable results. Its bounded supported modes and explicit nonclaims are authoritative in the module specification. Future signal, experiment, frame, execution-model, quantitative-composition, studies, replay, optimization, compute, adapter and presentation seams may become independent engines. No proposed acronym acquires authority merely through this list.

SQAV acquires input; SQMV declares metadata; SQFV controls buffer ownership; SQTV transforms; SQPV persists physical objects; SQDV delivers them. SBV owns experiment semantics, replay-window selection and result attribution. SNV may describe selected resources; SCV may supply explicit infrastructure evidence; SHV may process document artifacts. None is silently made mandatory. SSIAG governs selected authority circuits, STAV audit evidence, SKV contracts, SKVI discovery, SSFV capability records, SCLV change provenance, SEV evolution and SAV attribution retain their own owners. Broker data/execution remains SCABV/SOOV and must not be inferred from historical price observations. SIV/SMCV agent workflows and external AI tools are optional consumers, not universal execution authorities.

New studies and models must identify inputs, causality, units, support, weights, dependence, version, uncertainty and retention. Statistical advice must remain distinguishable from enforcement. Type/range/resource correctness may reject an invalid request; an engine must not silently replace valid user research choices. Every retained field must remain inspectable/exportable without requiring a GUI. Pure adapters preserve original provenance and cannot launder externally supplied outcomes into native-calculation claims.

The 0.3 experimental owner adds per-signal linear price economics, explicit nonexecution mixtures, unnormalized weighted sums and optional exact probability moments/quantiles. `qxctl sbv economics` consumes a digest-bound model result, preserves original census/replay context, and exposes every new field using the existing result contract. Signed coefficients remain distinct from probabilities. The user selects units, position/value, cost, nonzero return basis and domain-incompatibility policy. These are scenario transforms, not account/portfolio simulation. Exact current definitions and supported source layout are in `modules/sbv-engine/SPEC.md`.

The experimental 0.4 owner adds source-bound order-book reconstruction with exact census reuse, unknown-state semantics, reset/gap handling, caller-selected replay and depth, and portable full-state checkpoints. Ready frames describe a reconstructed observation, not a fill or queue estimate. The owner specification defines the exact strict Databento profile and current limits. Other user-authored profiles remain possible.

The experimental 0.5 owner adds typed displayed-depth execution scenarios, per-level participation, market/limit IOC/FOK intents, optional activation assumptions and independent/shared-snapshot modes. Conditional fills and calibrated execution remain distinct. Every outcome and selected study follows the portable terminal contract; quantity-aware economics was deferred in that release.

Experimental 0.6 adds quantity-aware markout on retained liquidity allocations, explicit cost components and optional activation mixtures/moments. Caller marks, units, rebates, signed nonzero return bases and inactive outcomes remain explicit. It preserves shared conditioning and complete replay; portfolio/account simulation remains deferred. See the owner SPEC for the exact bounded arithmetic contract.

Experimental 0.7 adds exact typed array selection, stable ordering and snapshot/query-bound pagination. Header-only backend/tensor ownership/completion types install independently, with explicit disconnected resource plans. A bounded offline live-shadow planner reports overload and pending windows and cannot activate a provider connection. All controls/results are exposed through qxctl.

Experimental 0.8 adds source-bound series analysis and supplied-trial comparison. Callers select data role, exact weighting, variance, quantiles, drawdown domain and explicit binary64 ratio estimates. Weighted scalar and Pareto comparison preserve completed/failed/pruned trial lineage; no executed optimizer or holdout validation is implied. Seventeen native operations and twenty qxctl leaves expose every produced field through shared immutable result access.

Experimental 0.9 adds deterministic uniform row/block bootstrap and private local native trial execution with immutable plans, claims, completions and explicit interruption ambiguity. Per-replica random streams preserve worker equivalence; local experiment reconciliation never silently retries an uncertain trial. Remote SOV operations and adaptive optimizer behavior remain separate.

Experimental 0.10 provides a separately consumed installed C ABI and C++ ownership wrapper for the same native operation/result contracts. External language bindings can use it without introducing an interpreter into the native package. CUDA/tensor runtimes, hostile-pointer isolation, zero-copy exchange and remote dispatch remain separate capabilities.
