# SHV private resumable materialization contract

qxctl owns private orchestration checkpoints; unchanged C++ engines own evidence interpretation and partition/manifest semantics. No catalogue head, source adoption, SSIAG grant or graph publication is performed. Mutability is evidence_only, as for existing local orchestration evidence.

Commands `shv materialization prepare|run|resume|status|export|schema|template`. prepare selects --prefix/--version partition engine and --input plan; all nondiscovery commands require explicit --job-root/--job-id. run/resume require --max-tasks integer1..8. Plan exactly `{tasks,required_references}`, tasks1..8 unique `{task_id,endpoint}` with the existing explicit refresh endpoint contract. Job ID is separate from future partition digests. Each task snapshots bounded bundle bytes and retains the endpoint; subsequent run/export never rereads bundle_path or substitutes its contents. Actual source files and exact source/kernel installations are still replayed.

prepare pins the partition installation, snapshots bundles, validates exact bundle/endpoint installation identities and seals `{protocol,job_id,installation,tasks,required_references,digest}`. A task exactly `{task_id,endpoint,bundle,completion}`, completion null or `{partition,replay}`. prepare is idempotent for the same complete task specification and snapshots; reusing a job ID for different intent rejects. Maximum checkpoint1MiB and native JSON bounds; prepare reserves256KiB and validates a fully completed projection against the JSON limits before accepting a job. The projection is admission accounting only and is never retained as replay evidence. This is a deliberately finite job, not atlas-wide capacity.

run/resume hold a private job lock and process at most max-tasks pending tasks in order. For each task, replay retained bundle through exact C++ owners and original protected source history, invoke exact partition_build, then atomically checkpoint completion. Completed tasks are retained and skipped on resume; status labels them retained evidence rather than fresh dependency verification. Failures leave prior completed checkpoints and pending work intact. A crash before a checkpoint may repeat pure native work; a crash after it resumes subsequent tasks. No mid-native-operation checkpoint is claimed.

export requires all tasks completed, independently replays every retained bundle and rebuilds every partition, compares exact retained partition identity, then invokes native manifest_build. Equal partitions from different policy tasks are deduplicated in first-seen order; all tasks remain in the job record. Required references are native exact references, not assumed resolved. The result identifies the job/checkpoint, manifest and fresh per-task replay proofs. Failure emits no successful manifest. Export is evidence, not publication, and observations are sequential, not a global atomic source snapshot.

status validates the complete retained checkpoint and independent partition correspondence without requiring source bytes or native processes. Its output explicitly says dependencies_not_replayed. Source history advancement does not silently upgrade pinned input; historical replay reports current-source observations as before. Local roots/endpoints remain fixed in this first job contract; explicit rebind and staged acquisition are later work.

Storage reuses attributed no-follow/openat/flock/fsync mechanics in separate `symphony/qxctl/shv/materializations-v1/<hash-of-job-id>/state.json`. Current-user private files, single links, checked ancestors, nonblocking lock, same-directory temporary write, file sync/rename/directory sync; uncertain post-rename durability is resolved by status/resume. No automatic pruning or repair of unsafe paths. Same-user file ownership plus seals is integrity checking, not publisher authentication.
