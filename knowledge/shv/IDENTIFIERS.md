# SHV documented identifier mapping v1

`AMD-PRODUCT-IDENTIFIERS.v1.md` is a versioned, source-specific mapping profile for AMD product-page boxed and tray IDs. It is a declarative knowledge artifact composed into existing native catalogue mapping fields; it is not a new engine, a new accepted top-level native request, an automatic profile loader or a universal identifier taxonomy. The installed C++ SHV kernel already implements the required exact string extraction and qualified equality, so native code and package versions remain unchanged.

The profile binds issuer=AMD, two distinct namespaces (product-id-boxed and product-id-tray), exact source labels/adjacency, source sections, predicates and qualifier strings. Issuer attribution is the caller-selected source publisher, not cryptographic authentication. The profile digest is tagged SHA256 over canonical JSON excluding digest. Source-specific layout changes require a separately reviewed profile version; do not silently update this v1 profile to a newer layout.

Compose the profile’s heading_section, field_section and fields into caller-selected SubjectSpec records, supplying exact source ID, subject ID, manufacturer, model and hardware class. Supply original captured bytes and source manifests to `qxctl shv catalogue build --prefix ... --version ... --input ... --json`, or use `shv refresh build` with protected source history for the same mapping. Neither the profile nor the parser discovers a source or decides which components the caller should use. Native source checks bind the exact bytes, model heading, adjacent field names, mapping and catalogue digest. Catalogue assertions retain source_id, predicate, qualifier and exact string value. Original bytes and mapping retain supporting labels and scope.

Boxed and tray IDs are separate namespaces. Do not strip prefixes, remove leading zeros or hyphens, fold case, convert to numbers, split values into tokens or equate boxed and tray IDs because their digits look similar. Existing HTML normalization still decodes entities and normalizes layout whitespace; this is an exact normalized field value, not a raw byte substring. The profile chooses value_type=string. Current kernel versions0.1.0-dev and0.2.0-dev support that field grammar; the acceptance packet explicitly selects0.2.0-dev without changing earlier selections.

`qxctl shv evaluate` applies caller requirements with exact predicate, qualifier, operator=eq and expected string. Native supported means this subject’s documentary identifier equals the selected value under that qualifier. Contradicted means a different documented value under that qualifier; it does not certify physical incompatibility. Unresolved means the requested evidence/qualifier is absent. A wrong namespace remains unresolved; no fallback or preferred source is chosen. These results do not establish physical identity, vendor aliases, provenance authenticity or transitive equivalence.

Native graph project/validate and the separately selected generic adapter preserve the original assertions and catalogue. Existing dossiers may cite their complete assertion digests; citations retain caller association authority. Coverage and introduction dates are separate: identifier-only mapping does not invent dates, and callers can add explicit introduction mappings or select a different coverage policy.

The initial evidence uses two different original AMD CPU product pages (7313 and7313P), not two independently agreeing documents for one component. It establishes independent extraction, exact comparison and visible disagreement/absence. Same-component cross-document agreement and vendor alias entailment remain further source work. No protected catalogue publication or new graph database is introduced.
