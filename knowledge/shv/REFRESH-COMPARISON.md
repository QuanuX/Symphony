# SHV refresh comparison contract v1

`qxctl shv refresh compare --input <request> --json` compares two fully replayed bundles. Request exactly `{previous,current}`. Each endpoint exactly `{bundle_path,source_root,state_root,tops_id,source_id,source_prefix,source_version,kernel_prefix,kernel_version}` with nonempty strings. All selections are caller-supplied; executable selection is never inferred from the bundle. Existing engine inspection enforces exact installation/version support.

Both endpoints must name the same TOPS and stable source ID. Cross-source equivalence is not inferred. Each bundle is read once with bounded no-follow admission, then those immutable bytes pass the existing native replay and independent consumer checks. No re-read of a mutable bundle pathname occurs between selection and verification. Historical revisions must belong to the selected committed source history. All stages complete before comparison output; a failed side emits no partial successful result.

Result protocol `symphony.qxctl.shv-refresh-comparison.v1`: TOPS/source identity, exact previous/current bundle digests, same_bundle boolean, previous_replay/current_replay full existing verification results, observation_scope=sequential_source_replays, causal_attribution=not_inferred, dimensions, subject_changes, assertion_changes, digest. Each replay reports its own observed current source digest. This is not a simultaneous two-source snapshot or subsequent freshness guarantee.

Dimensions are in fixed order: source, source_installation, kernel_installation, mapping, profile, subject_ids, requirements, capture_bodies, capture_manifests, capture_observations, catalogue, coverage, evaluation, source_graph, catalogue_graph. Each row contains dimension, changed, previous_digest,current_digest. Digests hash canonical `{value:<selected dimension>}`. Capture bodies use a sorted multiset of `<content digest>:<byte count>` strings: reordering or renaming a capture alone cannot imply different body bytes. Manifest and observation arrays preserve order. Observations retain capture fields except source, manifest and digest. This reports dependency differences, not vendor causation.

Subject changes compare full native subject metadata excluding assertions by exact subject ID. Assertion changes compare full native assertions by exact subject ID and predicate; native uniqueness already guarantees one assertion per predicate. Rows sort by subject ID, then predicate where applicable. Kind is added/removed/changed; missing previous/current is null. Added/removed means absence in this finite materialization, not hardware nonexistence or incompatibility. Qualifier, source reference and value remain intact. No alias/rebrand inference, unit conversion, compatibility judgment or conflict policy is added.

The existing refresh schema gains ComparisonEndpoint, ComparisonRequest, Dimension, SubjectChange, AssertionChange and Comparison definitions. `shv refresh template --operation compare` returns unanswered endpoint fields; default/explicit build retains the old template. The comparison output has the same formatted one-MiB bound. Each input bundle separately retains its existing one-MiB bound. Native engines and schemas are unchanged; qxctl provides structural presentation of already verified owner artifacts.
