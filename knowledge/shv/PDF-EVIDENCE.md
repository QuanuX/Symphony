# SHV opaque PDF evidence and interpretation boundary

The existing SHV source engine captures original PDF bytes as format=opaque, binds exact source revision and content digest, projects provenance graphs and revalidates bytes after generic adapter exchange. This behavior is implemented through qxctl. It does not extract hardware assertions from PDFs. A source-scoped subject declared by a caller is not evidence that its facts have been interpreted.

Independent source reconnaissance after IDENTIFIERS.md found a separate AMD publication carrying matching identifier strings for the previously selected CPU models. The product pages use Product ID Tray; the PDF table uses OPN. Literal string agreement and shared model text can be preserved as a research observation. They do not establish a general namespace equivalence or vendor alias contract. Diagnostic PDF text extraction and visual review are not native SHV interpretation.

The next document pipeline needs two separately explicit responsibilities: bounded decoding of original documents into derived content, and source-specific hardware interpretation. The decoder must preserve the original capture identity, selected decoder/code identity, page selection, output identity, transformation parameters and replay relationship. SHV interpretation must cite that derivation without treating transformed content as an independently published vendor source. Derived content must not count as a second corroborating document for its own parent.

Those derivation interfaces are design requirements for subsequent implementation, not implemented protocols. Generic document-decoder ownership and reusable integration with existing documentation vectors require review before assignment. No PDF library, shared service or universal decoder dependency is selected here. qxctl remains the first-class operating interface; callers must be able to choose exact tool versions and supported mappings.

Acceptance for a future native PDF path should cover original-byte tampering, decoder changes, reordered or duplicate table rows, missing or ambiguous cells, page-boundary tables, changed headings, mismatched namespaces and graph replay after transfer. Bounds must be explicit and failure must not silently truncate. OCR, scans, arbitrary PDF layouts and physical identity verification are separate coverage decisions.

The SHV-14 packet records acquired original bytes, research-only literal corroboration and successful opaque native capture/graph replay. Qualified machine corroboration remains unresolved until both the decoding/interpretation path and the namespace evidence are available. This document records the current boundary and prospective acceptance scope; it does not promote research observations into canonical hardware assertions.
