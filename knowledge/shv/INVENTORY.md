# SHV caller-owned coverage inventory

`qxctl shv inventory run|compare|schema|template` accounts for a caller-maintained roster against explicitly supplied refresh evidence. qxctl owns orchestration and accounting; independently installed C++ owners retain source interpretation and coverage semantics. No native package or operation version changes.

Run accepts exactly `{profile,roster,evidence}`. The profile is an exact native coverage profile; the caller selects `--prefix`, `--version`, and `--input`. Roster contains 0–32 uniquely identified entries with `id`, source-scoped `subject_id`, `manufacturer`, `model`, `hardware_class`, nullable `locator`, and nullable `evidence_id`. Evidence contains 0–8 uniquely identified `{evidence_id,endpoint}` entries using the refresh-comparison endpoint contract. All evidence is replayed, including unused entries. Missing references, malformed inputs and bounds violations reject; nothing is silently truncated. The existing one-MiB request limit applies. Locators are absolute URI declarations, not acquired or authenticated sources, and do not initiate network activity.

Each roster entry has one highest observed stage: expected (neither locator nor evidence), discovered (caller declares a locator), acquired (listed evidence replays but the requested subject has not been interpreted), or interpreted (the replayed catalogue contains the exact subject ID and matching manufacturer, model and hardware class). A label mismatch remains acquired with `roster_identity_mismatch`. Counts are disjoint, not cumulative. Acquired means the referenced bundle was acquired, not that it necessarily contains documentation for the expected subject. Interpreted means catalogue membership, not complete specification coverage, cross-source identity resolution or hardware compatibility certification.

Only an exactly matching catalogue subject can supply its introduction interval. Missing introduction remains null. Coverage is evaluated independently by the selected native kernel over caller roster IDs and labels. The default 2018 introduction-date policy can leave even interpreted subjects unresolved; an explicit caller policy may select them. Coverage inclusion alone establishes no evidence stage. Arbitrary caller hardware classes remain possible.

Results retain the entire request, stage rows/counts, native coverage result, replay observations, exact source/kernel installations and source/capture/mapping/catalogue dependency digests. The selected coverage installation is checked before and after evaluation. `dependency_validation=listed_evidence_sequentially_replayed` describes sequential observations, not an atomic filesystem snapshot. `locator_validation=caller_declaration` and `catalogue_published=false` remain explicit. The digest is an integrity seal, not authentication.

Compare accepts exactly `{previous,current}`, two complete inventory requests, and replays both. It returns complete observations and added/changed/removed stage rows in current order followed by removed prior entries. `change_scope=stage_rows_only` avoids claiming a complete semantic diff; `dimensions_changed` separately reports request, evidence and coverage changes, including policy-only changes with no stage delta. The coverage installation must remain identical across both observations. This is a fresh comparison, not a replay of the original time of a historical observation.

The maintained inventory consists of caller-saved requests and immutable observations; no global mutable roster or catalogue head is introduced. Schema and unanswered template discovery require no installation. `--json` provides structured errors as well as successful results. Canonical catalogue publication, automatic discovery/acquisition, subject alias unification and broad hardware coverage remain separate scope.
