# SHV source lifecycle contract v1

Adopted bounded SHV-02 implementation following the September 13, 2026 component-focused continuation. New independent C++26 package `shv-source-engine` version `0.1.0-dev`, engine `symphony-shv-source`, vector `shv`. Existing SHV kernel and generic adapter exact installations remain unchanged. Public process `symphony.knowledge.engine-process.v1`; strict canonical JSON, shared foundation request/response/deadline bounds. Owned feature `ssfv:symphony:shv-source-engine`; command administration continues `ssfv:symphony:qxctl.shv-administration`.

All objects reject extra/missing fields. `digest` is tagged SHA256 of canonical object without digest. Identifiers [A-Za-z0-9._-]{1,128}. Bounded text is nonempty UTF-8, no ASCII control/DEL. Hash strings exact sha256:64 lowercase hex. URLs are an explicitly limited http(s) profile: ASCII visible bytes, DNS-style host [A-Za-z0-9][A-Za-z0-9.-]* and optional canonical decimal port1..65535; no IPv6, userinfo, percent-encoding in authority, fragment, whitespace, controls, backslash, double quote, < or >. Scheme exactly lowercase http or https. No arbitrary fetch/authorization implied. URI bytes preserved; no automatic normalization or same-host assumption. Locators may move across domains in a plan.

## Source

Definition exactly `{source_id,publisher,authority_role,subject_ids,locators}`. Publisher and role max256 bytes, caller-declared authority scope, not authenticated. 1–32 unique subject IDs: component/family references, not physical Node identity or every server permutation. 1–16 unique locator IDs and unique URI strings. Locator exactly `{id,uri,format}` where format html|opaque. Order retained and significant. A source may be a family document; no mandatory one-page-per-component duplication.

Source revision exactly `{protocol:"symphony.shv.source-revision.v1",definition,generation,previous_digest,digest}`. Generation integer1..32. Generation1 has null previous_digest; later generations require digest. Stable source_id in a transition, while publisher/role/subject scope changes are explicit authority_change. This bounded release limits a full chain to32; partitioned history comes later.

`source_plan` input `{operation_id,current,desired,reason}` current null or Source, desired Definition, reason max4096. Output `{protocol:"symphony.shv.source-plan.v1",operation_id,expected_state_digest,change_kind,reason,source,digest}`. Kinds onboard,authority_change,relocation. Identical desired/current definition is rejected; generation exhaustion rejects. Source is recomputed generation+1, previous=current.digest; expected state null on onboard. Authority fields take classification precedence over relocation. Source_id replacement rejects.

`source_reduce` input `{current,plan}` validates current/plan, recomputes complete plan from current and plan's operation/reason/desired definition and requires equality. Output `{protocol:"symphony.shv.source-transition.v1",operation_id,expected_state_digest,source,digest}`. Pure candidate transition only: no persistence, approval, identity authentication, live source selection or protection bypass. qxctl exposes this accurately as read_only/invoke. Protected activation will require a separately adopted qxctl storage/SSIAG boundary; a JSON approval flag is not substituted.

`source_status` input `{history}` 1–32 revisions beginning at generation1, exact contiguous predecessor digests, stable source_id; repeated identical definitions reject. Output `{protocol:"symphony.shv.source-status.v1",source,history_digests,digest}`, where source is final revision. Caller-supplied history is verified internally, not authenticated as an active registry.

## Captures

`capture_import` input exactly `{source_root,source,locator_id,resolved_uri,redirect_chain,observed_at,upstream_revision,manifest,completeness,issues}`. Absolute lexically normalized source_root; current kernel no-follow file semantics. Source revision bound in full. Selected locator exists. 0–8 unique redirect destination URIs, excluding initial URI; resolved_uri equals final chain URI or selected locator URI if empty. Whole-second UTC YYYY-MM-DDTHH:MM:SSZ; valid calendar; no leap seconds. Optional upstream_revision null or `{scheme,value}` max128/512. It is not derived from time or ETag. Manifest exactly kernel Source `{id,path,bytes,digest,format}`: id is capture-specific catalogue ID, safe relative normalized path, 0..1MiB bytes, exact file hash/length, format matches locator. Completeness complete|partial; 0–32 unique issue strings max512; partial requires at least one issue. No network acquisition performed or publisher completeness certified.

Output Capture `{protocol:"symphony.shv.source-capture.v1",source,locator_id,resolved_uri,redirect_chain,observed_at,upstream_revision,manifest,completeness,issues,digest}`; source_root omitted. Replaying a capture revalidates its shape/seal and reruns import against actual file bytes.

`capture_compare` input `{source_root,previous,current}` with two replayed captures. Output `{protocol:"symphony.shv.capture-comparison.v1",previous_digest,current_digest,same_logical_source,changes,digest}`. changes contains in this fixed order, only when changed: source_identity (logical source_id), source_revision (full source digest), body (manifest digest or bytes), representation (manifest format), acquisition_route (locator_id/resolved_uri/redirect_chain), upstream_revision, completeness (completeness/issues), observation_time, manifest_identity (manifest id/path). These differences do not assert changed hardware capability.

## Graph and discovery

`graph_project` input `{source_root,captures}` 0–8 replayed captures, unique capture manifest IDs and capture digests, sum manifest bytes<=4MiB. Bundle `{protocol:"symphony.shv.source-bundle.v1",captures,digest}` retains input capture order. Output existing symphony.graph.exchange.v1. Owner engine_id=symphony-shv-source, engine_version=0.1.0-dev, artifact_protocol/source-bundle and digest. One `source-revision:<untagged source digest>` node per exact source revision, labels [source_revision], properties=full Source. One `capture:<manifest.id>` node per Capture, labels [source_capture], properties=full Capture. Edge `capture-source:<manifest.id>` from capture to source-revision, label captured_under, properties `{source_id,source_digest}`. Nodes/edges sorted by ID; duplicated source revisions share a node. No hardware assertions or canonical source activation implied.

`graph_validate` input `{source_root,graph}` reconstructs bundle/graph from full captures and verifies exact equality after source replay. Output `{protocol:"symphony.shv.source-graph-validation.v1",graph_digest,bundle_digest,valid:true,digest}`.

`inspect` empty input; descriptor.v2 with eight operations inspect,source_plan,source_reduce,source_status,capture_import,capture_compare,graph_project,graph_validate. Stable IDs `engop:symphony:shv-source.` + operation underscores replaced by dots. Input protocols `symphony.shv.`+operation underscores replaced by hyphens+`-input.v1`, except graph_project/validate use `symphony.shv.source-graph-project-input.v1` / `source-graph-validate-input.v1`; inspect uses `symphony.shv.source-inspect-input.v1`. All read_only/idempotent/authorization none, expected_state_required true for source_plan/source_reduce and false otherwise; interactions inspect for inspect/source_status, invoke for others. Generic foundation limits, scopes[user], language C++26, thermal freezing; canonical_apply/session_mutation/network_listener false. Contract versions [knowledge/shv/SOURCES.md@v1,symphony.shv.source-revision.v1,symphony.shv.source-capture.v1,symphony.graph.exchange.v1].

qxctl leaves `shv source inspect|plan|reduce|status|schema|template`, `shv source capture import|compare`, `shv source graph project|validate`. Every native leaf requires explicit --prefix --version; noninspect --input; --json. Schema/template discovery reuses CLI envelope protocols but reads only new receipt-owned resources `share/symphony/schemas/shv-source-engine/0.1.0-dev/source.schema.json` and source.templates.json. Executable `libexec/symphony/shv-source-engine/0.1.0-dev/symphony-shv-source`. Docs normal receipt-v2 module layout.
