# Protected SHV source activation through qxctl

Implemented CLI-owned journal contract `symphony.qxctl.shv-source-store.v1`. SHV source engine `0.1.0-dev` owns planning/reduction/history semantics; qxctl owns protected local selection and SSIAG owns permission decisions. The pure native `source_reduce` is not approval. This contract does not change hardware selection, evidence policy, publisher authentication, capture acquisition, catalogue selection or graph persistence.

## Exact operating interface

`qxctl shv source activation propose|apply|status|recover` requires explicit `--prefix`, `--version`, `--tops-id`, `--source-id`, and `--state-root`. Prefix/version select the independently installed SHV source engine. No default version, state root, source or TOPS is inferred. `--json` and the default output both preserve complete structured results. This release supports user scope on Darwin/Linux; unsupported platforms reject before filesystem mutation.

`propose --input FILE` accepts exactly `{operation_id,desired,reason}`. Current state comes from the locked protected store, not caller input. Desired source_id must match the selected stable identity. Output is the exact C++ SourcePlan, directly consumable by `apply --input PLAN`. Proposal does not adopt a source or obtain permission. Locks/directories may be created as filesystem mechanics, but no source head is published.

`apply --input PLAN` requires the exact source plan and current expected digest. Before permission, qxctl invokes the exact owner reducer, independently verifies its result, reinspects the installation and durably saves the plan, transition, installation and operation identity. `recover --operation-id ID` uses only that retained intent and the original receipt/executable identity; replacement input is not accepted. A completed exact replay returns the historical transition and attempt alongside the current head/history, without reduction against a newer head or moving that head backward. Reusing an operation ID with another plan or installation rejects.

`status [--operation-id ID]` returns the current source, ordered committed history and optional exact attempt. Unknown selected operation IDs reject. Nonempty history is also checked through installed source_status. An empty store has null source/head/owner_result and an empty history. It is not an onboarded source. `schema` and `template --operation propose|apply` expose CLI-owned contracts/unanswered templates with explicit prefix/version context and attributed SHV/SSIAG owner definitions. Templates are not valid inputs or evidence until completed. Activation failures requested with --json use the existing symphony.qxctl.error.v1 envelope and a nonzero exit; no error envelope claims that an uncertain write did or did not occur. Use status/recover to resolve retained state.

## Authority and publication

Actions are `symphony.shv.source.onboard`, `symphony.shv.source.relocation`, and `symphony.shv.source.authority-change`, selected by the exact native change kind. Resource is `symphony.shv.source:` plus hexadecimal SHA-256 of canonical `{tops_id,owner_engine_id:"symphony-shv-source",source_id}`. Audience is `qxctl`; scope is `tops:<UUID>`. Engine release is pinned in intent, not part of logical source identity. SCV permissions never stand in for these actions.

Before SSIAG is contacted, a random UUIDv4 authorization correlation is durably bound to the intent. Recovery reuses it; each fresh authorization request gets a new UUID and a requested one-minute lifetime. The authenticated SSIAG client verifies target/TOPS and complete request/decision/capability correspondence, subject, binding, policy/config digests, nontransferability, authority basis and expiration. Human and permitted-agent callers use the same permission contract; caller class is not an eligibility rule. A local JSON approval flag cannot substitute for SSIAG.

Journal states are prepared, authorized and committed. Permission failure leaves the intent prepared and the prior head unchanged. The journal stores actual allow decisions and up to64 prior allow decisions; denied requests remain in SSIAG's own audit and do not become allow evidence. Before changing head, qxctl durably saves the authenticated decision. It then flushes and closes the next private temporary file, reinspects the exact engine installation, rechecks both decision and capability expiry, and atomically renames the new head/status document under the same lock. The store additionally checks expiration. Directory sync completes durability. An error after rename may mean publication occurred with uncertain durability; status/recovery inspect disk before any repeated action.

STAV records the SSIAG policy decision. There is no fabricated source-write STAV receipt: result fields explicitly say `authorization_audit:"ssiag_policy_decision_only"` and `source_write_stav_receipt:null`. `canonical_apply_enabled:false` distinguishes this local protected selection from Symphony-wide canonical application; it does not mean that apply is read-only.

## Retention and validation

The store lives beneath `<state-root>/symphony/qxctl/shv/sources-v1/<tops-id>/<identity-hash>`, using the same canonical identity hash as its authority resource. Source identity remains the literal caller-selected source_id. The implementation uses narrowly reused descriptor-relative filesystem mechanics from the SCV store, attributed in source, with SHV-specific namespace and semantic validation. SCV store files/protocols are unchanged.

Ancestors must be root/current-user controlled; root-owned sticky temporary ancestors are supported. Selected descendants and files are private/current-user owned; source state and lock files must be regular and singly linked. No-follow openat traversal, nonblocking flock, exclusive temporary files, file sync, atomic rename and directory sync preserve the existing local trust model. Self-seals detect inconsistency; they are not cryptographic publisher authentication or protection from the owning user rewriting their own storage.

Every retained intent, including a non-head prepared branch, is independently reduced against its exact committed predecessor. Committed source generations form one contiguous chain from generation one, and selected head must be its terminal revision. Current head digest is source.digest, not the transition digest. Historical engine installation shape is retained without requiring all historical installations still to exist; replay/recovery requires the exact original installation available now. Historical permission evidence may be expired; unfinished publication always needs fresh authorization.

Bounds:128 attempts,16MiB canonical store,64 prior authorizations per attempt,32 native source revisions, and at most1,040,384 bytes for canonical source_status `{history}` payload (one MiB less8192 bytes reserved for process metadata). Prepare rejects prospective history overflow before retaining a new intent; persisted history is independently checked under the same bound. There is no implicit pruning or silent partial history. These are this finite adapter's limits, not universal limits on user hardware or tools; resumable/partitioned history is a later contract.

Exact CLI schema describes document, intent, attempt, proposal, result and discovery envelopes. Runtime checks additionally enforce canonical text/JSON, seals, native semantics, installation paths, ordered lineage, caller/permission correspondence and filesystem trust. Captures, source locations, accepted hardware facts and graph projections remain distinct objects; source adoption does not refresh or approve them automatically.
