# SHV immutable partition manifest contract v1

New independent C++26 shv-partition-engine0.1.0-dev, engine symphony-shv-partition, vector shv. Pure bounded operations inspect, partition_build, manifest_build, manifest_query. Existing source/kernel/adapter packages stay unchanged.

Partition input exactly `{dependencies,subject_ids}`. Dependencies exactly `{source_revision_digest,source_engine,kernel_engine,captures,mapping_digest,catalogue_digest}`. Engine references exactly `{engine_id,version,executable_digest}`; source symphony-shv-source0.1.0-dev, kernel symphony-shv0.1.0-dev or0.2.0-dev. Capture references exactly `{capture_id,capture_digest,content_digest,bytes}`, 1..8 unique IDs and capture digests, bytes0..1MiB,total<=4MiB, sorted by ID. Subject IDs0..32 unique, sorted. Output adds protocol=symphony.shv.partition.v1 and digest. Partition identity excludes coverage, requirements, TOPS, local installation/source roots and publication state. from-refresh computes mapping_digest as SHA256 of canonical `{mapping:<complete catalogue mapping>}`. Catalogue/capture digests still bind their recorded provenance, including immutable manifest paths.

Direct native partition_build validates reference declarations, not referenced bytes or publisher authority. qxctl `shv partition from-refresh` independently replays an explicitly selected refresh endpoint, then derives the exact dependencies and subject inventory before invoking the partition engine. It returns the partition, original bundle digest, replay verification and partition installation separately; query policy does not enter the native partition identity.

Manifest input exactly `{entries,required_references}`. Ordered entries0..64, unique partition_digest, each `{partition_digest,partition}` with full matching Partition or null for an expected unavailable partition. Required references0..128 unique pairs `{partition_digest,subject_id}`. Native output protocol=symphony.shv.partition-manifest.v1 preserves entries/references, adds ordered reference_statuses, loaded_count, missing_count, complete_inventory and digest. Status found|missing_partition|missing_subject|unlisted_partition. complete_inventory means all declared entries loaded only; it does not imply a complete hardware atlas, evidence authentication or resolved required references. Duplicate subject names in different partitions remain separate identities.

Query input exactly `{manifest,selection,limit,cursor}`. Full manifest is rederived and compared. Selection0..128 unique references, limit integer1..32. Null cursor begins at0. Cursor exactly `{manifest_digest,selection_digest,offset}` binds exact selected manifest and canonical selection; offset integer1..selection.length-1. Selection digest hashes canonical `{selection:[...]}`. Output protocol=symphony.shv.partition-query.v1: manifest_digest,selection_digest,offset,rows,total_selected,next_cursor,digest. Each row exactly `{reference,status}`; next_cursor null at end. Bounds do not silently truncate: only the selected page is returned, with explicit continuation. Caller-supplied offsets are seeks, not proof that earlier pages were processed. An absent subject means absent in that finite partition, never physical incompatibility.

qxctl `shv partition inspect|build|manifest|query|schema|template|from-refresh` administers every operation. Exact --prefix/--version required. Native leaves use --input except inspect. Template requires --operation partition_build|manifest_build|manifest_query. from-refresh --input is the SHV-06 endpoint object with explicit bundle_path/source_root/state_root/TOPS/source and source/kernel selections; it does not infer executable selection from artifacts.

All digests tagged SHA256 of canonical JSON without the digest field. Tokens [A-Za-z0-9._-]{1,128}; strict fields/integers, no extra/missing fields, duplicate references or resealed inconsistent manifests. Existing foundation request1MiB/response4MiB/value/depth/deadline bounds apply. No graph storage vendor, catalogue head, permissions, acquisition, materialization checkpoint or conflict aggregation is added. Sequential pages bind an immutable manifest, not a mutable latest alias.

## Explicit 0.4 composition admission

Partition 0.4.0-dev explicitly admits source 0.1/0.2 and kernel 0.1/0.2/0.3/0.4. Historical partition 0.1/0.2/0.3 retain their prior source/kernel admission. qxctl passes the selected partition owner through build, manifest, query, materialization checkpoint and resolution replay. The embedded previous-version macro retains the partition 0.2 semantics.

These exact component admissions are not a closed list of user modules. New providers, owners and tools remain extensible through their own contracts. No selected version is rewritten to latest.
