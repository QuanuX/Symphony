# Symphony Intelligence Vector Specification

## Agentic-First Boundary

Symphony contracts, names, operations, state, compatibility, and consequences must be understandable to agents without granting agents a separate authority class. Human, AI, service, and other callers use the same target-host ownership or explicitly granted permission model.

SIV may coordinate context and communication, but it does not duplicate the canonical truth of SQV, SOV, SCV, SNV, SHV, SKV, or another owner. It consumes owner contracts and returns bounded evidence through their supported surfaces.

## Future Capability Landscape

Future SIV research may consider:

- simultaneous local and remote agents;
- redundant agent participation;
- extended local context and task-scoped context projection;
- structured long-term logic and decision continuity;
- inter-agent messaging comparable in purpose to agent mail and beads;
- human-directed installation and operation at the Symphony surface;
- later integration of conversational requests into governed construction and deployment.

No listed capability is implemented or fully specified here.

## Context Surfaces

The Contract Quad, SKVI, `SLANG.md`, `NAMESPACES.md`, SCLV, SSFV, SEV, and owner-declared companions provide the canonical context foundation. SIV should derive task-scoped context from those sources rather than introduce restated shadow doctrine.

## IPC and Memory

Shared memory, local sockets, message fabrics, files, or other IPC mechanisms remain adapters to be selected by exact use case. No universal IPC or memory transport is chosen by this contract, and no administrative or agentic channel becomes an inline hot-path dependency.

## Non-Authorization Statement

SIV cannot infer permission, ratify a proposal, rewrite an owner contract, decide strategy behavior, expose secrets, or treat model output as execution authority.
