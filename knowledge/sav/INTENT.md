# Symphony Accordare Vector Intent

## Purpose

The Symphony Accordare Vector (SAV) defines how one exact Symphony composition is resolved and how declared relationships are evaluated for accord. It provides a deterministic focus of truth across independently owned vector, module, installation, binding, receptor, feature, command, operation, policy, audit, and temporal evidence.

SAV exists so a TOPS owner can ask which facts apply now, which relationships are satisfied, which are definitely contradicted, which cannot yet be resolved, and why.

## Source-Truth Boundary

`knowledge/sav/` owns:

- Accord Reference identity and grammar;
- CURRENT snapshot construction and coverage semantics;
- Named Version composition-envelope semantics;
- relationship and trait vocabulary;
- reference-resolution, composition-accord, and transition-readiness axes;
- deterministic evaluation, comparison, explanation, and disposable graph contracts.

SAV does not take ownership from the referenced source. SSFV remains feature truth, SKVI remains routing truth, SCLV remains reviewed change truth, SODV remains publication truth, SACV remains API-contract governance, SSIAG remains authentication and permission truth, STAV remains operational audit truth, package receipts and protected registries remain installation and selection truth, Maestro remains receptor-presence truth, and STSC remains temporal truth.

## CURRENT Intent

`CURRENT` is the conceptual name for one immutable `symphony.sav.current-snapshot.v1` observation. It is content-addressed, coverage-qualified, derived, read-only, and noncanonical. It binds exact typed source projections and unresolved sources without converting collection time into semantic identity.

`in_accord` means in accord only within the snapshot's exact declared and evidenced scope. Partial or unknown coverage cannot silently become complete.

## Caller-Neutral Intent

Any caller may use direct engine inspection within effective operating-system permissions. Protected host observation and administration require exact SSIAG host ownership or granted permission. Caller class is never an authority input. Human, AI, automation, service, workload, and system subjects use the same operation and permission rules.

## Thermal and Implementation Intent

The independently installable C++26 SAV engine is a freezing-path process. It consumes bounded caller-supplied evidence over strict local standard-input/output IPC. It has no network listener, performs no ambient host discovery, starts no service, and creates no hot/warm-path dependency.

qxctl is the preferred headless administrative client. It obtains exact source evidence, validates results, invokes the selected engine, and presents machine output. qxctl implements SAV contracts but does not own them.

## Non-Authorization Statement

SAV does not authenticate a caller, grant permission, mutate canonical knowledge, select the newest installation, activate or dock an engine, execute a lifecycle plan, append raw STAV events, seal a Named Version, persist a canonical graph, require AI, or claim completeness beyond exact evidence.
