# SAV Extension Capsules and Installation Blueprints

## Extension Capsule

An Extension Capsule is a portable declaration supplied by an independently developed module. It identifies exact package evidence, SSFV feature ownership, qxctl administrative coverage, engine operations, compatible Maestro receptor kinds, Accord References, traits, and one ratified extension point. It cannot grant itself a namespace, invent command grammar, authorize installation, or claim integration readiness when required evidence is absent.

The admission rule is fail-closed but non-exclusionary: an incomplete capsule remains inspectable and installable as an exact package, while semantic registration, administration coverage, selection, activation, or docking readiness report independently. This is the required edge-case behavior for third-party modules whose author did not initially provide qxctl coverage.

## Installation Blueprint

An Installation Blueprint is a noncanonical, content-addressed desired-composition plan. It names exact components and optional Capsule/Named Version bindings, declares both forward and reverse dependency edges, and identifies default receptors without making them mandatory. qxctl may override a default through an explicitly administered lifecycle profile.

The planner computes a ready set from verified observation on every step. A failed linear order does not force the entire plan to fail: unaffected dependency branches remain ready, retryable blockers remain localized, and reverse actions use the same evidence and ordering rules. Hard safety edges are never dynamically bypassed.

## Ownership

SAV owns these composition contracts. SSFV owns feature identity and worthiness. qxctl owns command truth and orchestration. Receipt v2 owns installed package evidence. Maestro owns presence. SSIAG owns permission. STAV owns safe audit event truth. The coordinator owns durable procedure state. None may silently substitute for another.
