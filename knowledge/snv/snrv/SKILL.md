# Symphony Node Resource Vector Skill

## Procedure

1. Resolve the physical Node through SNIV.
2. Separate local hardware, software/Habitat state, and remote or virtual attachments.
3. Treat a material local hardware change as an SNIV consequence.
4. Preserve evidence source, observation time, and unresolved conflicts.
5. Refer detailed hardware capabilities to SHV and operational changes to SOV.

## Stop Conditions

Use the admitted v1 owner schema for supplied inventories. Preserve guest exposure, unknown coverage and remote attachment distinctions. Materiality decisions stay with SNIV; additional probe, shorthand or mutation behavior requires a separately admitted contract.
