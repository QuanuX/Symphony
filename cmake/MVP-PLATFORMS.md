# MVP platform profiles

`mvp-platform-profiles.json` declares the exact qualification targets. It is not evidence that a build passed. The required sprint profiles are macOS 15 Apple Silicon, Ubuntu 24.04 x86_64, Ubuntu 26.04 x86_64 and Ubuntu 24.04 ARM64. The user accepted Ubuntu ARM64 for this sprint without physical DGX Spark access. Native Windows is unsupported and no port is planned. WSL2 or SSH can provide access to Linux, but do not inherit filesystem or native Windows qualification.

Each `tests/platform-qualification/capture.sh PROFILE /absolute/work` run records the actual kernel, OS release, architecture, compiler, C/C++ runtime package or SDK, selected work filesystem and source commit/tree. Its `symphony.platform-observation.v1` output has `status: observed` and `qualification_status: evidence_only`; the exact source/test result and this file's digest must be bound by the release evidence producer. A declared profile, runner label or successful metadata capture is not a test result. A dirty source state is retained explicitly.

macOS packages target deployment 15.0 and LP64 ARM64, use libc++ and preserve independent native owner/SDK identities. Ubuntu 24.04 starts from glibc 2.39 and GA kernel 6.8; Ubuntu 26.04 uses glibc 2.43 and GA kernel 7.0. Updated HWE/cloud kernels and runtime packages are recorded exactly per run, not inferred from those baselines. The C++ SDKs require matching compiler/runtime ABI; the DuckDB integration uses the pinned engine's stable C API and packages its platform-specific shared library adjacent to the executable. No CUDA dependency is introduced by either CPU connector.

The selected local test filesystem is recorded (APFS on macOS, ext4 targeted on Ubuntu). The native storage contracts retain caller-selected filesystems with coherent inode identity, `flock`, no-follow paths, atomic rename and synchronization semantics. The gate records the filesystem actually used; it does not turn successful system calls, SIGKILL recovery or a VM test into a power-loss durability proof. Ubuntu 26.04 may use tmpfs for `/tmp`; qualification work is placed in the selected runner workspace/temp volume and its real filesystem is recorded. Other filesystems need explicitly bound evidence rather than an invented runtime allowlist.

The optional physical Spark profile records DGX OS 7, its exact image/kernel/driver/CUDA and GB10 device observations. NVIDIA's current 7.6 reference image uses Ubuntu 24.04.5, kernel 7.0.0-1018-nvidia, driver 580.173.02 and CUDA 13.0 Update 3; repository updates can differ. Metadata observation does not attest hardware identity or test GPU behavior. There is no physical Spark claim in this change and no self-hosted runner is provisioned.
