For SRRAPIV, `allow_provider_calls`, `allow_trading` and method allow-lists are
local admission. `account_ref` is correlation; it does not filter native
`AccountInfo` parameters. A provider call's return is not a filled, cancelled or
reconciled order. The queue's 4,096-event / 4 MiB bounds make loss visible; they do
not form a lossless execution journal. Runtime stop, cancellation request,
flattening and economic risk enforcement remain distinct. No new universal user
policy or mandatory architecture is introduced by this qualification example.

The state/fault oracle must keep at least these outcomes distinct:

| Trigger | Required owner observation | Forbidden inference |
| --- | --- | --- |
| Duplicate same attempt / conflicting request | Retained identity returned / digest conflict refused | Automatically redispatch under a new attempt ID |
| Loss before/after durable dispatch admission | Exact persisted phase and independently observed effect | Timeout means no effect or safe automatic retry |
| Missing completion persistence | Prior `outcome_unknown` retained; new effects inhibited where the owner specifies | Queue emptiness means success |
| Duplicate/reordered callbacks or visible gap/overflow | Generation/cursor/lost-count evidence and provider-specific reconciliation | Bounded queue is a complete account ledger |
| Wrong native account or provider/local disagreement | Actual account identity and authoritative endpoint query | Local `account_ref` guarantees economic account enforcement |
| Stop during a blocked SDK operation | Existing busy/stop-blocked/stopping/stop-failed disposition | Host stop cancels or flattens provider orders |
| Lost status reply / owner restart | Generation-bound retained evidence and unresolved readiness | Repeated mutation to discover what happened |
| Capacity refusal / active writer | Acknowledged bytes preserved and new work refused as contracted | Deleting history or enlarging limits to manufacture a pass |

Any promised economic limit, stale-market-data guard, lossless ledger or
provider reconciliation without a selected implemented owner remains a D03
blocker. A user may select an external composition, but no such composition is
silently added or certified here.
