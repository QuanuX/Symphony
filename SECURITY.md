# Security reporting

Do not post vulnerabilities, credentials, account identifiers, private data or exploit details in public issues. A private intake destination and response owner have not yet been approved; this is a launch blocker, not a monitored security service or promised response time.

Before launch the release owner must publish and test an authorized private channel, name its primary and backup responders, and document acknowledgement, disclosure and supported-version policies. GitHub private vulnerability reporting may be selected only after repository administrators enable and verify it; its availability is not assumed here. Until that channel is confirmed, retain sensitive details privately and request a private reporting route from the project maintainers without posting the vulnerability itself.

For ordinary non-sensitive defects use the issue form. Static-analysis success does not establish absence of vulnerabilities; the dated CodeQL triage and its open findings remain separate evidence.
